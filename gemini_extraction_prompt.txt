Extract ALL line items from this procurement document, including duplicates.
Also extract key header/reference fields from the document as described below.

============================
SECTION A — HEADER FIELDS
============================

Depending on which document type this is, extract the following header fields.
These appear in the document header, cover page, footer, letterhead, or as part of a logo/stamp.

For a PARTNER PO document (purchase order from a partner/reseller to Cyberknight):
  - reseller_name     : The name of the company that issued this PO (the buyer / partner / reseller).
                        Look first in text (company name, "From:", "Issued by:", letterhead, footer).
                        If not found in text, look in any logo or image at the top of the document
                        and read the company name from the logo.
                        Return null if genuinely not found.
  - partner_po_ref    : The PO number / purchase order reference.
                        Look for headers like "Purchase Order", "PO Number", "PO #", "Order Number",
                        "Order Ref", "Reference". Return the value exactly as printed (e.g. "PO-2024-00123").
                        Return null if not found.
  - partner_po_subtotal : The document's Subtotal — the sum of all line items BEFORE tax, VAT,
                        shipping, freight, or any other charges are added. Determine this value
                        in the following order:
                          1. If a row explicitly labeled "Subtotal", "Sub Total", "Sub-total",
                             "Net Total", "Total (excl. tax)", or similar is present — usually near
                             the bottom of the document, above the tax/VAT line and the grand/final
                             total — use that value directly.
                          2. If no such row exists, but the document shows a Grand/Final Total AND a
                             separate Tax/VAT amount (e.g. "VAT 5%: 1,350.00", "Tax: 200.00"), then
                             CALCULATE: partner_po_subtotal = Grand/Final Total − Tax/VAT amount.
                             This is the expected case for many documents that only show a
                             tax-inclusive total with a VAT breakdown line, not an explicit
                             "Subtotal" label.
                          3. If there is only a single Total (no separate "Subtotal" row) AND no
                             tax/VAT line or tax amount appears anywhere in the document at all —
                             i.e. there is genuinely no tax being applied — then that single Total
                             IS the subtotal (with zero tax, Subtotal = Total by definition). Use
                             that value directly. Do not return null just because the word
                             "Subtotal" itself doesn't appear — confirm first whether any tax/VAT
                             is present anywhere in the document before deciding there's nothing to
                             subtract.
                          4. If it is genuinely unclear whether the single total shown includes tax
                             or not (e.g. tax is mentioned but no amount is given, or the document
                             is unreadable in that area), return null rather than guessing.
                        Under NO circumstance return a tax-inclusive total as the subtotal — a value
                        that still contains VAT/tax is not a valid subtotal, regardless of which rule
                        above produced it. Return a numeric value only — no currency symbol, no
                        thousands separators.
                        Example (rule 1 applies — explicit Subtotal row present):
                          "Sub Total   167,402.17"
                          "VAT (5%)    8,370.11"
                          "Total       AED175,772.28"
                          → partner_po_subtotal = 167402.17 (read directly from the "Sub Total" row).
                          Do NOT calculate 175772.28 − 8370.11 here even though it produces the same
                          number in this example — rule 1 (explicit label) always takes priority over
                          rule 2 (calculation) whenever an explicit Subtotal/Sub Total row is present.
                          Only calculate Total − Tax when NO such explicit row exists at all.

IMPORTANT — reading reference numbers precisely (partner_po_ref, vendor_quote_ref):
  - These are exact identifiers, not descriptive text — a single wrong digit makes the
    value a different reference number entirely, so treat them with more care than
    ordinary prose.
  - Read the value character-by-character rather than recognizing it as a whole shape
    at a glance. Count each digit individually before returning it.
  - Pay particular attention to runs of repeated or similar-looking digits (e.g. consecutive
    zeros, or sequences like "00", "11", "000") — these are the most common place for a
    digit to be silently added, dropped, or duplicated. Explicitly recount the number of
    digits in any such run before finalizing the value.
  - Double-check the total character count of the reference number against what is visually
    printed — do not let the value "round off" to a more familiar-looking number or pattern.
  - If a digit is genuinely unclear (blurred, cut off, low resolution), extract your best
    single reading of that digit rather than guessing a different digit that seems more
    plausible — do not silently insert or drop a digit to make the number "look right" or
    more typical.
  - This precision requirement applies specifically to partner_po_ref and vendor_quote_ref.
    It does not change how line item fields (Section B) are extracted.

IMPORTANT — for logo/image extraction:
  - Gemini can read text embedded in images and logos natively.
  - If the company name only appears as part of a logo image (not as plain text), still extract it.
  - Return the extracted name as a plain string (no formatting).
  - If you are uncertain about the name read from a logo, still return your best reading — do not return null just because it was extracted from an image.

============================
SECTION B — LINE ITEMS
============================

IMPORTANT RULES:
1. Extract EVERY line item row — even if it looks identical to another row
2. Do NOT deduplicate or merge rows — if the same SKU appears 3 times, return 3 separate entries
3. Do NOT assume repeated rows are errors — they represent separate line items
4. Each physical row in the document = one entry in your output
5. Only skip rows that are clearly headers, totals, subtotals, taxes, shipping, or page numbers

For each line item return exactly these fields:
- line_num        : line number as it appears in the document (if none, use sequential 1, 2, 3...)
- sku             : product code or SKU exactly as written (use null if missing or not present)
- description     : full product description exactly as written, no truncation
- quantity        : numeric value only, no units (use null if not present or not readable)
- list_unit_price : numeric value only, no currency symbols, no commas — follow these rules in order:

  PRICE EXTRACTION RULES (apply in this order):
  a. If the document has a "Unit Price" column (or similar: "Price", "Rate", "Unit Rate"):
       - Use that value as list_unit_price
       - If the value is "-", "–", "N/A", blank, or empty → return 0
       - If the value is not present or genuinely unreadable → return null
  b. If the document has NO unit price column but has a "Total Price" column
     (or similar: "Extended Price", "Ext Price", "Line Total", "Amount"):
       - Calculate: list_unit_price = Total Price ÷ quantity
       - Round to 2 decimal places
       - If quantity is null, 0, or missing → return null
       - If Total Price is "-", blank, or 0 → return 0
  c. If neither a unit price nor a total price column exists → return null

Do NOT include: totals, taxes, dates, addresses, payment terms, or currency symbols.
